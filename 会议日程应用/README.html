领导会议日程 · Meeting Scheduler

把一段会议通知原文，变成一张排得清清楚楚的领导周历，再一键写进金山文档。

某市住房和城乡建设局 · 内部办公工具

这是什么

办公室每天要处理的事：收会议通知 → 判断该谁去 → 排进日程 → 填进共享表格 → 临时有人请假再改一遍。

这套流程过去靠人脑 + 手工敲表，一份通知三五分钟，一周十几场会，改一次就要重排一次。

这个工具把中间全部自动化：

通知原文  ──▶  自动拆出 日期 / 时间 / 地点 / 会议名 / 参会领导
          ──▶  按分工判断该谁去（含 AB 角备选）
          ──▶  排进周视图日历，撞车自动标红
          ──▶  一键写进金山文档对应格子

零依赖、免安装、打开即用。全部逻辑压缩在一个 index.html 里，双击就能跑。

核心功能

一、粘贴即解析：认得十几种日期写法

不用按格式填表，把微信里收到的通知直接粘进来就行：

1. 10月26日（星期一）上午9:00，在B027会议室召开局党组会议，请谷六副局长参加。
2. 2026-10-27 14:30 市政府三楼会议室 全市住建领域安全生产工作会议 韩七
3. 10.28 下午3点 我局五楼会议室 物业管理工作例会 杜四

一次解析出 日期 / 时间 / 地点 / 会议名称 / 参会领导 五个字段。

写法示例
中文10月31日、10月31号、2026年10月31日
短横 / 斜杠10-31、10/31、2026-10-31
点号10.31、2026.10.31、11.5日
空格10 31、2026 10 31
星期周四、下周三、星期一

同时主动避坑：14:30 不会被当日期，3.5 米 不会被当日期，5 楼 3 号 不会被当日期。 跨年自动判断，今年可省略年份。

一格/一行里挤了多场会也能分开。云文档里经常见到这种写法：

1.14:30，在市政府5楼2号会议室，参加严秘调度房地产事项会议；
2.15:45，在市政府3楼会议室，参加扫黑除恶大会。

按分号或「编号 + 时间」切开，逐场各自取自己的时间、地点、会议名—— 不会出现"时间取了第一场的 14:30、名字却取了第二场"这种串场。 只有自带时间的片段才算新的一场，所以 …会议；请各科室准时参加 这种补充说明不会被误拆成两场。

解析结果先进预览区，逐条核对后再「导入到日历」——不做"粘进去就已经写表"这种不可逆操作。

二、周视图日历：一眼看清谁在哪

  • 三色区分会议层级：市政府层面（红）/ 局内部（绿）/ 市直部门（灰）
  • 卡片上直接写 时间 + 会议名 + 参会领导，不用点开猜
  • 点卡片即可就地编辑，改时间、改人、改地点都在原地完成
  • 底部附下周预览，避免樊五才想起来下周一会撞车

三、冲突检测：只报数，不刷屏

同一个领导同一天两场会，间隔小于 90 分钟 → 自动判定冲突。

顶栏不逐条罗列，只给一行统计：

⚠ 本周 3 场会议存在时间冲突（涉及 2 位领导）　　[查看明细 ▾]

点「明细」才展开具体是哪几场。不打扰你的日常视野，但需要时随时能查。

四、内置领导分工：自动推荐该谁去

工具内置了局领导班子分工表和 AB 角关系。解析完一场会，它会顺手给出参会建议：

建议说明
主参会人按分管领域匹配（如"招投标"→ 分管建筑管理口的领导）
备选 / AB 角主参会人不在时该找谁，直接写在旁边
理由一句话说清为什么是他，不用自己回翻分工文件

分工规则可在「⚙ 分工与规则」里随时修改，改完立即生效。

五、一键写进金山文档：不覆盖、不重复、不写错格

这是整套工具最省事的一环。

  • 按日期找行、按领导找列，内容追加到格子，原有登记原样保留
  • 日期行不存在 → 自动插到正确位置并补上星期
  • 写入前先读云上最新内容 → 已登记过的自动跳过，不产生重复
  • 同一场会地点对不上 → 主动提示，让你确认而不是默默覆盖
  • 时间比对兼容两种写法：网页的 15:00 能对上云文档的「下午3:00 / 下午3点 / 下午3时」 （但必须有「下午/晚上」标记才认，避免把上午9点和下午3点误判成同一场）
  • 表里没有对应列的领导 → 明确列为「本次不写入」，不会静默丢数据

六、读回 + 反同步：删了也能撤回

动作效果
⟲ 读回云文档把云上已登记的会议拉回日历，合并处理，不重复、不删本地
自动读回服务在线时，每次打开页面自动拉一次最新
删除同步日历里删掉的会，同步时会提示「需同步撤下 N 处登记」，一键从云文档移除

删除是精确到段落的：只删匹配的那一条，同一格里的其他会议原样保留，整格只剩这一条时才清空。 中途失败不丢数据（先写新的，再删旧的）。

反过来也做了保护：你在云文档里手工删掉的登记，同步时不会被偷偷写回去。

  • 每个"我们写过的格位"都留一笔记忆（date|领导 + 写入时刻）
  • 下次同步时，如果云上快照比这笔记忆更新、且该格位是空的 → 判定为"人工删掉了"，列进「已查不到，本次不写回」
  • 确实要补回，点「仍然写回」才写（走 ignoreExisting）
  • 快照比记忆旧时不套用这条规则——宁可照常写，也不能因为快照过期漏写

七、对账模式：写之前先看清楚

除了点按钮，还有三个命令行地址，适合让工具代跑或无人值守：

地址作用
?mode=preview预演：只比对、列出将要写入什么，不动云文档
?mode=audit对账：双向查漏——云上缺什么、网页缺什么、一致多少
默认正式同步：读回 → 比对 → 只写缺的部分

每次执行的明细都会追加写入日志，事后可以逐条核查"到底写了什么"。

八、人员状态：调出、借调、休假自动识别

共享表格里有时写的不是会议，而是 「调出」「借调」「休假」「退休」 这样的状态字。

  • 这些字不会被当成一场叫"调出"的会议
  • 标记为「已调出」的领导：不再往他的列写新登记，调出生效日之后的会议不再计入统计
  • 但调出之前他参加的会议照常计入（那时他还在本单位），排名里名字后带一个「调出」小标， 统计卡底部会写清"调出前 N 场已计入、调出后 M 场不再计入"
  • 职务保留在名册里，不会变成"未登记职务"
  • 判断错了，一键移出名单即恢复

九、口头称呼也能认人

通知原文里很少有人写全名，多是"请崔局参加""谷局主持""贺主任汇报"。这些叫法会被落到具体人身上：

  • 姓 + 局 / 局长 → 先找职务为"局长"的那位（韩局 → 安一，而不是同姓的贺八）；同姓只有一人时直接认定（崔局 → 崔三、谷局 → 谷六）
  • 姓 + 主任 / 书记 → 按职务对（贺主任 → 贺八、周书记 → 安一）
  • 推荐参会领导时，称谓的优先级高于分管关键词：即使正文里有"安全生产"这类会指到别人的词，写了"崔局"就以崔局为准，预览里会标注"依据称谓「崔局」识别"
  • 已调出的人不会被推荐，但仍可以从名册里手动选
  • 我局 市住建局 分局 全局 这类不是称谓，不会被误认

十、参会统计：周 / 月一键切换与明细悬浮层

统计卡顶部有 周 | 月 切换：

  • 周：跟随日历当前周
  • 月：出现 ‹ 2026年10月 › 翻月，标题自动变成「本月领导参会统计」
  • 排名 + 明细双层展示，谁开得多一眼看出
  • 点任意一位领导，浮出明细层：逐条列出这段时间他参加的每一场会（日期 · 星期 · 时段 · 会议名 · 地点），带「复制」按钮；再点一次或按 Esc 收起
  • 该领导本期有培训的，额外标紫色「训 N 天」标签
  • 底部一键复制名单（月口径自动变成"复制本月参会名单"）

十一、外出培训：日历里也要占位

领导外出培训期间，日历上必须有痕迹，否则容易被误排会。

  • 登记：领导 / 起止日期 / 培训名称 / 地点
  • 跨天培训每天占位，卡片显示「第 2/3 天」
  • 日历上以紫色虚线卡呈现：🎓 杜四 · 外出培训 · 地点
  • 若这几天还给他排了会，卡片上红字警告「这天还安排了 N 场会给他」
  • 统计页按培训天数排名，形式与参会统计完全一致
  • 支持导出 CSV、复制名单时单列【外出培训】段

快速开始

方式一：只看日历、解析文字

双击 index.html 即可。无需安装任何东西，能解析、能看日历、能复制名单、能导出备份。

方式二：要写金山文档（推荐）

# Windows 下双击即可，等价于：
node bridge/server.mjs
  1. 双击 启动同步服务.bat
  2. 浏览器自动打开 http://127.0.0.1:7788/
  3. 点右上角「⬆ 同步云文档」→「登录金山文档」→ 在弹出的页面点「同意」
  4. 状态变绿「● 已连金山文档」，以后点「立即同步」直接写表

登录凭证只保存在本机 bridge/.auth.json，不出现在网页、不进日志。

黑窗口关掉 = 服务停止，网页其他功能照常可用。

常见问题

提示「未知接口」或「删除需要新版同步服务」

命令窗口里的进程跑的还是旧代码（改了 bridge/*.mjs 必须重启才生效）。

关掉黑窗口 → 重新双击 启动同步服务.bat → 浏览器按 Ctrl+F5。 登录凭证在本地，重启不用重新登录。

数据存在哪？换电脑怎么办？

网页数据存在浏览器 localStorage。换电脑或清缓存前，点「⇅ 数据 → 导出 JSON」备份； 云文档本身是主要留档，最坏情况也能用「读回」重新拉回日历。

为什么有的领导不出现在表里？

共享表格的列是固定的，表里没有对应列的领导会明确列为「本次不写入」， 不会静默丢掉，也不会写错人。同理，已调出的领导不再写入。

写错了能撤回吗？

把日历里那条删掉，再走一次「同步云文档」→「只删除这 N 处，不写入」， 就只做删除、不碰其他内容。删除精确到段落，同格其他会议不受影响。

设计取舍

几个刻意的决定，用久了会体会到：

  • 预览优先：解析完不直接入库，先让你核对。因为排错会比排慢更麻烦。
  • 追加优先：写入永远是追加，不覆盖。宁可重复被跳过，也不覆盖别人刚填的内容。
  • 报数优先：冲突只报「N 场」，明细收进抽屉。日常视野必须干净。
  • 自检优先：服务版本不对就明说，不让用户对着"未知接口"猜。
  • 单文件优先：不引入框架、不搞构建。一个文件丢进 U 盘就能用，这是办公场景的硬需求。
