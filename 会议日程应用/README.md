## 这是什么

办公室每天要处理的事：**收会议通知 → 判断该谁去 → 排进日程 → 填进共享表格 → 临时有人请假再改一遍**。

这套流程过去靠人脑 + 手工敲表，一份通知三五分钟，一周十几场会，改一次就要重排一次。

这个工具把中间全部自动化：

```
通知原文  ──▶  自动拆出 日期 / 时间 / 地点 / 会议名 / 参会领导
          ──▶  按分工判断该谁去（含 AB 角备选）
          ──▶  排进周视图日历，撞车自动标红
          ──▶  一键写进金山文档对应格子
```

**零依赖、免安装、打开即用**。全部逻辑压缩在一个 `index.html` 里，双击就能跑。

## 核心功能

### 一、粘贴即解析：认得十几种日期写法

不用按格式填表，把微信里收到的通知直接粘进来就行：

```
1. 10月26日（星期一）上午9:00，在B027会议室召开局党组会议，请谷六副局长参加。
2. 2026-10-27 14:30 市政府三楼会议室 全市住建领域安全生产工作会议 韩七
3. 10.28 下午3点 我局五楼会议室 物业管理工作例会 杜四
```

一次解析出 **日期 / 时间 / 地点 / 会议名称 / 参会领导** 五个字段。

| 写法 | 示例 |
|---|---|
| 中文 | `10月31日`、`10月31号`、`2026年10月31日` |
| 短横 / 斜杠 | `10-31`、`10/31`、`2026-10-31` |
| 点号 | `10.31`、`2026.10.31`、`11.5日` |
| 空格 | `10 31`、`2026 10 31` |
| 星期 | `周四`、`下周三`、`星期一` |

同时**主动避坑**：`14:30` 不会被当日期，`3.5 米` 不会被当日期，`5 楼 3 号` 不会被当日期。
跨年自动判断，今年可省略年份。

**一格/一行里挤了多场会也能分开**。云文档里经常见到这种写法：

```
1.14:30，在市政府5楼2号会议室，参加严秘调度房地产事项会议；
2.15:45，在市政府3楼会议室，参加扫黑除恶大会。
```

按**分号**或**「编号 + 时间」**切开，逐场各自取自己的时间、地点、会议名——
不会出现"时间取了第一场的 14:30、名字却取了第二场"这种串场。
只有自带时间的片段才算新的一场，所以 `…会议；请各科室准时参加` 这种补充说明不会被误拆成两场。

> 解析结果先进**预览区**，逐条核对后再「导入到日历」——不做"粘进去就已经写表"这种不可逆操作。

### 二、周视图日历：一眼看清谁在哪

- 三色区分会议层级：**市政府层面**（红）/ **局内部**（绿）/ **市直部门**（灰）
- 卡片上直接写 **时间 + 会议名 + 参会领导**，不用点开猜
- 点卡片即可**就地编辑**，改时间、改人、改地点都在原地完成
- 底部附**下周预览**，避免樊五才想起来下周一会撞车

### 三、冲突检测：只报数，不刷屏

同一个领导同一天两场会，间隔小于 **90 分钟** → 自动判定冲突。

顶栏不逐条罗列，只给一行统计：

> ⚠ 本周 3 场会议存在时间冲突（涉及 2 位领导）　　[查看明细 ▾]

点「明细」才展开具体是哪几场。**不打扰你的日常视野，但需要时随时能查。**

### 四、内置领导分工：自动推荐该谁去

工具内置了局领导班子分工表和 **AB 角**关系。解析完一场会，它会顺手给出参会建议：

| 建议 | 说明 |
|---|---|
| **主参会人** | 按分管领域匹配（如"招投标"→ 分管建筑管理口的领导） |
| **备选 / AB 角** | 主参会人不在时该找谁，直接写在旁边 |
| **理由** | 一句话说清为什么是他，不用自己回翻分工文件 |

分工规则可在「⚙ 分工规则」里随时修改，改完立即生效。

### 五、一键写进金山文档：不覆盖、不重复、不写错格

这是整套工具最省事的一环。

- **按日期找行、按领导找列**，内容**追加**到格子，原有登记原样保留
- 日期行不存在 → 自动插到正确位置并补上星期
- 写入前先读云上最新内容 → **已登记过的自动跳过**，不产生重复
- 同一场会**地点对不上** → 主动提示，让你确认而不是默默覆盖
- 时间比对兼容两种写法：网页的 `15:00` 能对上云文档的「下午3:00 / 下午3点 / 下午3时」
  （但必须有「下午/晚上」标记才认，避免把上午9点和下午3点误判成同一场）
- 表里没有对应列的领导 → 明确列为「本次不写入」，不会静默丢数据
- **改了时间 / 地点也会同步**：同一场会在云文档里已有登记、但写的时间或地点是旧版本时，
  会**就地替换那一段**（不是再追加一条）。判断依据是会议名称，所以连「当初只写了会名」的粗登记
  也能补全时间和地点；同一格里有多场会时，只换命中的那一场，其余原样保留
- 卡片角标会区分三态：`✓` 云文档已是这个版本 / `⟳` 云文档里是旧版本，等待写回 / `!` 云文档里已被删

### 六、读回 + 反同步：删了也能撤回

| 动作 | 效果 |
|---|---|
| **⟲ 读回云文档** | 把云上已登记的会议拉回日历，**合并**处理，不重复、不删本地 |
| **自动读回** | 服务在线时，每次打开页面自动拉一次最新 |
| **删除同步** | 日历里删掉的会，同步时会提示「需同步撤下 N 处登记」，一键从云文档移除 |

删除是**精确到段落**的：只删匹配的那一条，同一格里的其他会议原样保留，整格只剩这一条时才清空。
中途失败不丢数据（**先撤旧的，再写新的**，两步都在同一次同步里完成）。

反过来也做了保护：**你在云文档里手工删掉的登记，同步时不会被偷偷写回去**。

- 每个"我们写过的格位"都留一笔记忆（`date|领导` + 写入的是哪一场会：标题 / 时间 / 地点）
- 下次同步时，如果云上快照比这笔记忆**更新**、且该格位**是空的**、而且记忆里那场会跟现在这场**完全一样**
  → 判定为"人工删掉了"，列进「已查不到，本次不写回」
- 记忆里那场会和现在这场**不一样**（改过时间、地点，或者换了一场会）→ 照常写回。
  否则只要改过一次，这场会就永远同步不上去
- 把旧登记主动撤下之后，格位的记忆一并作废
- 确实要补回，点「仍然写回」才写（走 `ignoreExisting`）
- 快照比记忆**旧**时不套用这条规则——宁可照常写，也不能因为快照过期漏写
- 升级说明：老版本的格位记忆只存了时间戳、没存"写的是哪一场会"，没法判断，**升级后一次性作废**
  （只影响升级那一刻的旧记录）

### 七、对账模式：写之前先看清楚

除了点按钮，还有三个命令行地址，适合让工具代跑或无人值守：

| 地址 | 作用 |
|---|---|
| `?mode=preview` | **预演**：只比对、列出将要写入什么，不动云文档 |
| `?mode=audit` | **对账**：双向查漏——云上缺什么、网页缺什么、一致多少 |
| 默认 | **正式同步**：读回 → 比对 → 只写缺的部分 |

每次执行的明细都会追加写入日志，事后可以逐条核查"到底写了什么"。

### 八、人员状态：调出、借调、休假自动识别

共享表格里有时写的不是会议，而是 **「调出」「借调」「休假」「退休」** 这样的状态字。

- 这些字**不会被当成一场叫"调出"的会议**
- 标记为「已调出」的领导：**不再往他的列写新登记**，调出生效日**之后**的会议**不再计入**统计
- 但**调出之前**他参加的会议**照常计入**（那时他还在本单位），排名里名字后带一个「调出」小标，
  统计卡底部会写清"调出前 N 场已计入、调出后 M 场不再计入"
- 职务保留在名册里，不会变成"未登记职务"
- 判断错了，一键移出名单即恢复

### 九、口头称呼也能认人

通知原文里很少有人写全名，多是"请崔局参加""谷局主持""贺主任汇报"。这些叫法会被落到具体人身上：

- 姓 + `局 / 局长` → 先找职务为"局长"的那位（`韩局` → 安一，而不是同姓的贺八）；同姓只有一人时直接认定（`崔局` → 崔三、`谷局` → 谷六）
- 姓 + `主任` / `书记` → 按职务对（`贺主任` → 贺八、`周书记` → 安一）
- **推荐参会领导时，称谓的优先级高于分管关键词**：即使正文里有"安全生产"这类会指到别人的词，写了"崔局"就以崔局为准，预览里会标注"依据称谓「崔局」识别"
- 已调出的人不会被推荐，但仍可以从名册里手动选
- `我局` `市住建局` `分局` `全局` 这类不是称谓，不会被误认

### 十、参会统计：周 / 月一键切换与明细悬浮层

统计卡顶部有 `周 | 月` 切换：

- **周**：跟随日历当前周
- **月**：出现 `‹ 2026年10月 ›` 翻月，标题自动变成「本月领导参会统计」
- 排名 + 明细双层展示，谁开得多一眼看出
- **点任意一位领导，浮出明细层**：逐条列出这段时间他参加的每一场会（日期 · 星期 · 时段 · 会议名 · 地点），带「复制」按钮；再点一次或按 `Esc` 收起
- 该领导本期有培训的，额外标紫色「训 N 天」标签
- 底部一键**复制名单**（月口径自动变成"复制本月参会名单"）

### 十一、外出培训：日历里也要占位

领导外出培训期间，日历上必须有痕迹，否则容易被误排会。

- 登记：领导 / 起止日期 / 培训名称 / 地点
- 跨天培训**每天占位**，卡片显示「第 2/3 天」
- 日历上以**紫色虚线卡**呈现：`🎓 杜四 · 外出培训 · 地点`
- 若这几天还给他排了会，卡片上**红字警告**「这天还安排了 N 场会给他」
- 统计页按**培训天数**排名，形式与参会统计完全一致
- 支持导出 CSV、复制名单时单列【外出培训】段
- 云文档里只有首末两天标了「外出培训」也能认：**同一领导、同一培训名称的多处标记会并成一段连续培训**（相邻标记间隔 ≤ 45 天才合，隔得远的两段不会硬捏成一段），不会再被读成「只培训了那两天」

### 十二、冲突裁决与培训记录：跨设备同步

点过「连开/衔接」「判为冲突」「忽视」，**手机 / 同事电脑打开时不会再来问一遍**。

- 这些裁决和外出培训记录，除了存本机，还会写进云文档里另开的一张 **「应用状态」** 表
- **主表《会议安排》一个字符都不动**（不污染给人看的日历，也不会被当成会议读回来）
- 裁决 key 用「领导 + 日期 + 两个开始时刻」，**不再用事件 id**——id 是每台设备各自生成的，用 id 拼的 key 换设备必然对不上（这正是以前手机上重复提示的根因）；旧版本按 id 存的裁决会自动迁移
- 同一条记录**谁的更新时间新谁生效**，两台设备同时改也不会互相抹掉
- 培训记录只同步「用户自己登记或改过的」；从云文档标记自动收进来的不反向写回
- 用户删掉/改窄的培训留一条墓碑记录，云端标记不会把它重新撑回去

### 十三、一键重启同步服务

改了 `bridge/server.mjs` 或提示「服务是旧版本」时，**不用重启电脑**：

`更多 ▾ → ⟳ 重启服务`

服务自己退出，守护进程随即用磁盘上的新代码拉起（登录凭证在本机，不用重新登录），页面自动刷新。
服务跑在计划任务的高权限下，普通窗口杀不掉它，所以只能走这条「自己退出」的路——
`run-daemon.vbs` 里的 `.restart` 清理逻辑，就是给「上一任高权限进程还赖着」这种极端情况兜底的。

## 快速开始

### 方式一：只看日历、解析文字

双击 `index.html` 即可。无需安装任何东西，**能解析、能看日历、能复制名单、能导出备份**。

### 方式二：要写金山文档（推荐）

```bash
# Windows 下双击即可，等价于：
node bridge/server.mjs
```

1. 双击 `启动同步服务.bat`
2. 浏览器自动打开 `http://127.0.0.1:7788/`
3. 点右上角「⬆ 同步云文档」→「登录金山文档」→ 在弹出的页面点「同意」
4. 状态变绿「● 已连金山文档」，以后点「立即同步」直接写表

登录凭证只保存在本机 `bridge/.auth.json`，**不出现在网页、不进日志**。

> 黑窗口关掉 = 服务停止，网页其他功能照常可用。
>
> 开机自启走的是另一条路：计划任务 → `run-daemon.vbs` → 隐藏启动守护进程，
> **不产生任何可见窗口**。只有上面这种手动双击 `.bat` 的方式才会显示黑窗口。

## 技术说明

### 架构

```
index.html  单文件 · 约 3,700 行 / 190 KB
  界面 + 解析器 + 日历 + 统计，数据存 localStorage
        │
        │ fetch（同源）
        ▼
bridge/server.mjs  :7788
  静态托管 + 云文档接口
  ├─ kdocs.mjs           金山文档连接与登录（MCP）
  ├─ sheet-engine.mjs    读表 / 写表 / 删表引擎
  ├─ app-state.mjs       跨设备共用状态（云文档「应用状态」表）
  ├─ extract_local.mjs   docx / pdf / doc 文本提取（docx·pdf 纯 Node 零依赖；doc 走 word-extractor）
  └─ doc-snapshot.js     云文档现状快照（离线去重依据）
```

### 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/ping` | 健康检查，返回 `version`、`features` 能力清单与登录态 |
| POST | `/api/login/start` | 发起金山文档授权登录 |
| GET | `/api/login/status` | 轮询授权结果 |
| POST | `/api/logout` | 清除本机登录凭证 |
| GET | `/api/snapshot` | 拉取云文档当前内容 |
| POST | `/api/push` | 写入（已存在则跳过；时间/地点改过的**就地替换**那一段，返回 `replaced`） |
| POST | `/api/remove` | 移除指定登记（精确到段落） |
| POST | `/api/report` | 写回同步执行明细（落 `.tmp/sync-log.jsonl`） |
| GET | `/api/state` | 读「应用状态」表（冲突裁决 / 外出培训），`?force=1` 跳过缓存 |
| POST | `/api/state/push` | 合并写入「应用状态」表（同 key 谁的 `at` 新谁生效） |
| POST | `/api/restart` | 服务自己退出，由守护进程用新代码拉起（`更多 ▾ → ⟳ 重启服务`） |

网页启动时先对 `features` 自检：缺 `remove` 就直接提示「服务是旧版本，点这里重启」，
**不会抛出看不懂的接口报错**。

### 文件解析（零依赖）

| 格式 | 由谁解析 | 依赖 |
|---|---|---|
| `.docx` | `bridge/extract_local.mjs`（解 zip → 读 `word/document.xml` → 提取段落与表格） | 无，只用 Node 内置 `zlib` |
| `.pdf` | 同上（按 `/ToUnicode` 解码字体，按 Y 坐标聚行） | 无，只用 Node 内置 `zlib` |
| `.doc`（Word 97-2003） | `bridge/extract_local.mjs` → `word-extractor`（纯 JS，能正确处理 WPS 写的不完全标准的 OLE） | `npm install word-extractor`（在「会议日程应用」目录） |
| 图片（png/jpg/...） | `bridge/extract_file.py` → rapidocr | 需本机 Python 装有 rapidocr |
| `.wps` / `.ofd` / `.rtf` / `.xls` / `.ppt` 等 | **不解析**，直接给中文提示让用户转成 `.docx` 或 `.pdf` | 无 |

**为什么改掉 python-docx / pypdf**：WorkBuddy 升级自带 Python 时会整目录换掉 `site-packages`，
这两个包直接消失，于是拖进 .docx 就弹「No module named 'docx'」。docx 和 pdf 用 Node 解压 + 读 XML 就够，
没有任何理由依赖外部包——现在 Python 只负责真做不了的 OCR。

- **图片才走 Python OCR**；其它任何非 `.docx`/`.pdf`/`.doc` 的文本格式（`.wps`/`.ofd`/`.rtf`/`.xls`/`.ppt` 等）一律在 Node 侧直接给中文提示，
  绝不丢给 OCR 去报看不懂的 Python 错
- `.doc`（Word 97-2003 老格式）现在**直接解析**（走 `word-extractor`，纯 JS，能正确处理 WPS 写的不完全标准的 OLE 复合文档）；
  被改了扩展名、实为 docx 的 zip 会被自动按 docx 解析
- 早期版本把 `.doc` 误送 OCR 弹出「本机缺少解析组件」的内部报错，已彻底改为本地解析；若 `word-extractor` 未安装，会提示在「会议日程应用」目录执行 `npm install word-extractor`
- 解析失败时，文件夹监听的卡片上会多一个 **「重试解析」** 按钮（升级后不必把文件再放一遍）
- Python 的原始报错会被 `pythonErrorHint()` 翻成人话（例如缺 OCR 会提示改用截图粘贴）

## 常见问题

<details>
<summary><b>提示「未知接口」或「删除需要新版同步服务」</b></summary>

服务进程里跑的还是**旧代码**（改了 `bridge/*.mjs` 必须重启才生效）。

点 `更多 ▾ → ⟳ 重启服务` 即可（页面会自动刷新）。登录凭证在本地，重启不用重新登录。
如果这个旧服务连「重启」指令都不认，**重启一次电脑**，之后就能一键重启。
</details>

<details>
<summary><b>数据存在哪？换电脑怎么办？</b></summary>

网页数据存在浏览器 `localStorage`。换电脑或清缓存前，点「⇅ 数据管理 → 导出 JSON」备份；
云文档本身是主要留档，最坏情况也能用「读回」重新拉回日历。
</details>

<details>
<summary><b>为什么有的领导不出现在表里？</b></summary>

共享表格的列是固定的，表里没有对应列的领导会明确列为「本次不写入」，
不会静默丢掉，也不会写错人。同理，已调出的领导不再写入。
</details>

<details>
<summary><b>写错了能撤回吗？</b></summary>

把日历里那条删掉，再走一次「同步云文档」→「只删除这 N 处，不写入」，
就只做删除、不碰其他内容。删除精确到段落，同格其他会议不受影响。
</details>

## 设计取舍

几个刻意的决定，用久了会体会到：

- **预览优先**：解析完不直接入库，先让你核对。因为排错会比排慢更麻烦。
- **追加优先**：写入永远是追加，不覆盖。宁可重复被跳过，也不覆盖别人刚填的内容。
- **报数优先**：冲突只报「N 场」，明细收进抽屉。日常视野必须干净。
- **自检优先**：服务版本不对就明说，不让用户对着"未知接口"猜。
- **单文件优先**：不引入框架、不搞构建。一个文件丢进 U 盘就能用，这是办公场景的硬需求。
